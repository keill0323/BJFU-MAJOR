# 业务回归测试

在项目根目录运行，无需启动后端或连接开发、生产数据库：

```powershell
& .\.venv\Scripts\python.exe -B -m unittest discover -s backend/tests -t backend -v
$testFiles = @(Get-ChildItem -LiteralPath backend/tests -Filter 'test_*.js' -File | ForEach-Object { $_.FullName })
node --test @testFiles
```

后端使用标准库 `unittest` 和项目现有依赖；前端使用 Node 内置的 `node:test`、`assert` 和 `vm`，无需安装测试框架。

历次验证结果统一记录在[项目日志](../../项目总结与踩坑记录.md)；请以实际运行输出判断当前通过数。数据库升级命令见[部署指南](../../deploy.md)。

`support.py` 在独立临时目录加载测试配置，不读取项目 `.env`。每个后端测试创建独立 SQLite 数据库并启用外键；并发用例使用自动清理的临时 SQLite 文件和两个独立进程。上传、AI 和小程序 API 都使用模拟响应，不访问实际截图、微信或线上服务。


招募与消息回归：`test_recruitment_notifications.py` 覆盖未报名招募、队长权限、公开字段白名单、申请人身份与学号隐私、主页消息隔离、满员/分组限制、迁移幂等及微信出站队列。微信请求全部模拟，覆盖授权归属、重复事件、超时不重发、过期/已处理/隐藏事件和令牌刷新。`test_recruitment_ui.js` 覆盖游客浏览、页面竞态、订阅点击授权、主页分类计数及三个入队入口的选填自我介绍。

QQ 停用回归：`test_team_captain_qq.py`、`test_team_qq_ui.js` 验证无 QQ 建队、旧字段不保存/不展示、旧联系入口停用、游客/登录者/管理者响应隐私及历史迁移保留；`test_wechat_qq_reminders.py` 验证旧配置不再暴露用途、授权不再催填、历史队列跳过及正常申请/邀请继续发送。

申请生命周期回归：`test_team_request_lifecycle.py` 覆盖通过申请、接受邀请、直接入队和创建队伍后的旧请求自动失效；退队、踢人、解散及管理员删队不会恢复历史申请。验证来源申请保持通过、无关用户不受影响、成员与失效标记共同回滚，以及列表/计数/微信过滤和旧表迁移幂等。

## 覆盖的业务约束

- 图片隐私授权：`test_privacy_upload_ui.js` 使用真实页面、全局监听与组件配合模拟微信接口，覆盖认证截图、段位截图、队标和头像的原请求恢复；同意必须来自专用按钮并携带匹配 ID，拒绝/卸载结束等待，并发请求不丢失。另覆盖指引打开、加载失败重试、迟到响应、已授权跳过弹窗及选图取消/权限异常。其他页面测试仅模拟新增错误处理依赖；微信真机授权核验仍需体验版验证。
- 管理员定向通知：`test_admin_notices.py` 与 `test_admin_notices_ui.js` 覆盖收件人搜索和字段白名单、管理员权限、显式多人选择、限额、原子发送、请求幂等、跨账号收件隔离、已读同步、分页/异步竞态、失败重试及新表幂等迁移。测试只写隔离数据库或模拟 API，不向真实用户发通知。
- 队伍列表按晋级阶段与名次排列，同名次并列、种子仅稳定排列；半决赛晋级、轮空与冠军判定不依赖接口中的胜负字段。用户端和管理端点击卡片查看分阶段对局，BO3 按整场统计，地图小分以本队为先；未结束、缺结果和轮空不虚增胜负。
- 出局名次按奖金档划分，挑战者组第三、第四不能合并；覆盖三组 16 队、四组 16/20 队、缺失队伍但历史对阵保留、完全同分与未完成赛程。进行中只显示阶段，不提前标最终奖金名次。

- 管理员可补录已结束赛事的历史冠军，允许队伍/选手无账号关联、未知比分留空，人工备注与操作人不进入公开响应；审核员、普通用户和未登录者不能补录。
- 人工冠军保存版本校验、事务回滚、自动冠军防覆盖；解除账号关联保留历史资料，迟到战队导入不能恢复关联；迁移保留已有冠军及 SQLite 自定义索引且可重复执行。
- 管理待办按实际认证与报名状态聚合，队伍成员不重复计数；摘要固定两条只读 SQL。各入口共用摘要，退出/切换账号清除，审核成功失效，过时请求不恢复已清理角标，网络失败不误报无待办。
- 管理页默认待办总览，按栏目加载列表，队伍调用管理接口包含待审记录；审核及返回刷新计数，待办提示与列表错误状态各自保留、可重试。
- 首页名人堂复用快捷入口，保留原有功能；每个已注册非首页都有可见的返回赛事入口。返回准确定位已有首页、保留筛选状态，无首页历史时直接打开；重复点击合并，返回失败可降级并重试。
- 名人堂仅根据完整六强淘汰赛决赛生成冠军；错误晋级关系、缺失对阵、无胜者或单独修改赛事状态不产生冠军。
- 比分与冠军快照同事务提交，失败全部回滚；更正或反转结果使用原始双方阵容，队伍更名、转会、段位变更不改写历史。无效比分暂时撤回荣誉，恢复有效结果时保留原始资料。
- 删除赛事后保留冠军档案，`match_available` 关闭失效入口；公开查询仅执行 SELECT，回填必须显式执行且幂等，并标记历史阵容和未知夺冠时间。
- 冠军写入查询使用 MySQL 当前读语句；测试对 MySQL 方言编译的锁查询进行断言，不等同于实机 MySQL 并发验证。
- 段位榜覆盖全部加号段位与 S 星级，按认证段位排序而非水平分；同段同星跨页并列、稳定排序，待审核申请及非法段位不进入有效排名，公开响应只包含允许的资料字段。
- 名人堂前端覆盖独立页签、触底防重、分页及刷新响应竞态、失败保留数据与重试、卸载后不更新页面、阵容展开和导航入口。
- 学号唯一且有效才可自动认证；AI 异常、重传、迟到响应不影响人工审核。
- 首次段位无法自动识别时进入人工申请队列，批准时必须指定有效段位。
- 个人报名转整队报名统一待审；队伍审核通过后才建立赛事进度。
- 已通过、未分配种子且无组别的队伍显示「待分组」，不计入实际挑战者队伍；待审核和驳回报名不误标为待分组。
- 已有种子、组别、后续阶段或对阵即锁定参赛名单；新队伍报名、新旧审批入口和自动补报名均不能绕过。已批准队伍重复审批保留种子、组别和阶段，自由人与既有参赛队伍按原规则补成员仍可处理。
- 种子与分组通过一次原子请求保存；非法组别、人数不足及事务中途异常都不留下部分编排，生成对阵后仍不能重分。双进程测试覆盖分组与审批两种竞争顺序。
- 管理端隐藏锁定后的审批按钮，确认框再次检查名单；分组防重复提交，失败保留数据，成功后即使详情刷新失败也保持审批关闭。
- 邀请和申请只能处理一次；成员、报名和评分在同一事务内修改。
- 多进程竞争最后一个队伍名额时，仅一人成功；未结束新生赛退队或踢人后仍需至少三名新生。
- 小组和附加赛完整结束后才可晋级；淘汰赛名次保留对未晋级队伍的成绩。
- 对阵生成后不能重新分配种子或分组；晋级后不能直接修改前序比分。无组别的手动对阵仍可录分和更正。
- 16 队三组含附加赛、20 队四组无附加赛均从分组推进到决赛；对阵生成途中失败不会提交半份赛程。未完成前序晋级不能提前分传奇区。
- 个人已报名的队长可以提交队伍报名；尚未生成对阵的阶段可以查看并编辑已保存的时间窗口。
- 前端改版：赛事筛选与搜索竞态、加载失败重试、导航在途用户请求复用、游客不拉取个人消息、队伍详情真实评分与队长派生、段位/截图展示、头像更新与登录防重。
- WXML 条件链校验覆盖全部模板和隐藏弹层，防止 `wx:else`/`wx:elif` 与 `wx:for` 同节点、条件链中断；人才市场加载/失败/空列表/选手列表互斥显示。
- 段位徽章覆盖全部现有段位及 S 星级边界，首页、认证页和个人资料使用同一映射。
- 整队审核使用正确的赛事与队伍 ID；缺失接口、业务 404、权限及登录失效分别处理，审批失败不显示成功。
- 报名时间支持创建、修改和清除，按北京时间验证；前端防止重复提交，保存不改赛事状态和报名数量。
- 排期范围依据真实三组、四组及自定义组显示；无赛程时仍读取分组和已存窗口，挑战者、附加赛、传奇、淘汰赛分类正确。
- 三组显示附加赛，四组隐藏附加赛及推进操作；旧窗口不影响组数，隐藏阶段后页签索引不会越界。

这些用例不替代真实 MySQL 和微信真机验证。`champion_snapshots` 缺失表可由启动流程创建，已有表的字段升级必须显式迁移；冠军历史回填也需显式执行。验证与发布状态见[项目日志](../../项目总结与踩坑记录.md)。

测试数据隐藏回归：`python -m unittest tests.test_test_data_visibility -v`。覆盖公开队伍列表和详情、管理员回溯权限、隐藏选手后的榜单名次与分页、人才市场、冠军快照展示、历史对手匿名化和可重跑的增量迁移。隐藏标记不依据昵称自动设置，不删除账号或改写比赛结果。

旧数据若显示报名已通过但缺少赛事进度，管理端会显示待审核；仅在尚未编排、名单未锁定时可使用“通过报名”补齐。已经分组的赛事不能借此新增参赛队伍。已经产生的错误晋级或不合资格阵容不会被脚本自动重写，需要管理员核对后处理。

全部选手与历史赛事补员：覆盖未报名/已入队/未认证用户、昵称与游戏 ID 搜索、学号不参与目录搜索、身份动态判定与人工覆盖，以及申请通过后的新老生显示。已结束赛事不限制当前组队、不新增历史报名；仍在进行的赛事保留原认证、人数及新增队伍限制。
