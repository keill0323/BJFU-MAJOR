# 2026-09-07 管理时间与分组修正

## 报名时间单独设置

管理后台创建赛事时可选择报名开始、截止日期和时间；已有赛事进入详情后，顶部新增「报名时间」按钮，可回显、修改及清除限制。

- 所有报名时间按北京时间解释，支持只设开始、只设截止或两端都不限制。
- 日期和时间需要成对填写；同时设置两端时，开始必须早于截止。
- 保存期间防止重复提交，失败保留输入；成功只更新详情中的报名时间，不覆盖现有报名数量。
- 时间设置不自动切换赛事状态。赛事必须处于「报名中」且满足所设时间范围，用户才可报名。

新增 `PUT /api/matches/{match_id}/registration-window`，沿用管理权限检查和赛事行锁。请求必须显式包含 `register_start` 与 `register_end`，以 `null` 清除对应限制。无时区日期作为北京时间保存；带时区输入先转换北京时间。创建、个人报名、整队报名共用时间规则，不依赖服务器操作系统时区。沿用现有边界：恰好开始、恰好截止时刻允许报名。

## 排期范围按真实分组显示

原「时间窗口」改称「比赛排期范围」，用于限定双方队长协商的比赛时间，与报名时间分别管理。

移除固定 A–F 占位项，按当前赛事的队伍分组、历史对阵和已保存的窗口合并显示：三组显示 A/B/C，四组显示 A/B/C/D；没有队伍或对阵但已保存的分组保留，并注明来源。尚未分组且没有保存窗口时显示空状态。

| 实际分组 | 页面名称 |
| --- | --- |
| A、B、C 等 | 挑战者组 · A 组等 |
| 自定义组名 | 挑战者组 · 原组名 |
| 附加赛（三组赛制） | 挑战者组 · 附加赛 |
| 上区、下区 | 传奇组 · 上区 / 下区 |
| 淘汰赛 | 淘汰赛 |

编辑窗口时展示完整阶段名称，提交仍使用原始组名。用户端与管理端赛程也取消 A–F 白名单，自定义组名的对阵及历史淘汰队伍不会因此消失。

## 三组与四组采用不同晋级流程

按用户确认的赛制，前 4 支队伍直升传奇组，各挑战者小组冠军也晋级传奇组；是否设置附加赛取决于普通小组数量。

| 挑战者组数 | 附加赛 | 传奇组 8 个名额 |
| --- | --- | --- |
| 三组 | 各组第 2 名打单循环，冠军晋级 | 4 支直升 + 3 个小组冠军 + 1 个附加赛冠军 |
| 四组 | 不生成附加赛，各小组其余队伍淘汰 | 4 支直升 + 4 个小组冠军 |

后端结束小组赛返回 `group_count` 和 `has_playoff`，管理端根据真实结果提示下一步。四组不能额外调用附加赛晋级接口。小组赛或附加赛尚未完成晋级时不能提前分传奇区，避免旧逻辑在恰好已有 8 支传奇队伍时越过未结束的比赛。

用户端与管理端按队伍及历史普通小组对阵识别组数，四组隐藏附加赛页签与推进操作，三组保留。刷新、切换赛事时校正当前页签索引，防止隐藏附加赛后出现空页。独立保存的旧窗口不会影响当前组数判断。

当前固定 8 队传奇组的流程支持三组或四组；分组入口和服务校验同步限制这两种赛制。旧版本已经错误生成的附加赛、晋级记录不自动删除或重写，需要管理员核对；四组历史附加赛不再作为当前正常赛段展示。
