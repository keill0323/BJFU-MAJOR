# 2026-09-08 名人堂功能

名人堂已实现「赛事冠军」和「选手段位」两个板块，首页与抽屉导航已加入入口。本轮交付小程序前端及真实配套 API；尚未部署后端、上传或发布小程序，线上状态没有改变。

## 页面与交互

- 赛事冠军：按日期倒序展示冠军队徽、队名、赛事名称、决赛比分和对手，可展开查看阵容。
- 选手段位：展示平台最高段位与选手榜，复用完整段位徽章，支持 A+、C+ 及金 S、钻 S、魔王 S 等。
- 两个列表独立加载和分页，支持下拉刷新、失败重试、空状态；迟到响应不会覆盖刷新后的数据，重复触底不会叠加请求。
- 原赛事删除后保留冠军档案，根据 `match_available` 隐藏失效的赛事详情入口。

## 冠军来自真实决赛

后端校验当前六强淘汰赛的完整五场对阵：两场四分之一决赛、两场半决赛、一场决赛均完成，比分与胜者一致，晋级队伍关系正确。未完成决赛、对阵缺失或仅把赛事改为「已结束」都不会发布冠军。

新增 `champion_snapshots` 表，在有效决赛首次录分时保存双方队伍及成员快照，与比分一起提交。队伍更名、成员变动、段位更新或原记录删除后，已保存的荣誉不随之改变。更正比分同步冠军结果；反转冠军时使用另一方的原始快照，无效结果撤回展示但保留快照供恢复。

写入时沿用赛事锁，并使用 MySQL 当前读查询快照与决赛链，避免等待锁后仍读取旧版本。快照保存失败会一并回滚比分。

已有赛事不会在访问页面时自动生成档案。显式执行 `backfill_champions` 可归档完整决赛，重复执行不覆盖已有记录。回填的阵容来自归档时资料，无法证明夺冠当天阵容；返回 `snapshot_source=backfill`、`awarded_at=null`，页面明确提示历史阵容的来源。

## 段位榜规则

排名只使用已生效的认证段位，顺序为：

`D < C < C+ < C++ < B < B+ < B++ < A < A+ < A++ < S0 ... S50`

S 段按星数降序，同段同星并列，例如 `1、1、3`，并列项按用户 ID 稳定排列；旧值 `S` 与 `S0` 同级。数据库先排名再分页，避免各页重新从 1 排名。水平分与待审段位申请不影响榜单；学籍认证不作为额外准入条件。公开响应不包含学号、截图或微信标识。

## 接口与发布边界

| 接口 | 说明 |
| --- | --- |
| `GET /api/hall/champions` | 冠军档案，默认每页 20 条 |
| `GET /api/hall/players` | 选手段位榜，默认每页 50 条 |

两接口均为公开只读，接收 `offset`、`limit`，上限每页 100 条。前端页为 `/pages/hall/hall`。

此次新增数据库表，与上一次「待分组」修复无新增表的结论不同。后端现有启动建表流程会创建 `champion_snapshots`；历史冠军回填需要显式执行，不会自动改写原赛事、队伍或比分。前端与后端需配套发布。此前手动部署包 `20260908-135210` 不含名人堂，发布该功能需使用包含新 `hall` 模块的当前后端代码；本轮按前端交付范围，不创建新部署包，也未执行部署。
