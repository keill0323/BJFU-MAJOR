# 2026-09-07 报名审核接口排查

## 问题与已确认原因

管理后台赛事详情的「通过报名」按钮显示 `Not Found`。本次只读检查了正式服务器的 [公开 OpenAPI](https://bjfumajor.com/openapi.json)，没有使用真实登录令牌、审批实际报名或修改线上数据。

前端 `miniprogram/utils/api.js` 当前连接 `https://bjfumajor.com`。按钮使用的接口与本地后端一致，但尚未出现在此次检查的线上接口清单中：

| 项目 | 实际接口 |
| --- | --- |
| 当前前端调用、本地后端已实现 | `POST /api/matches/{match_id}/registrations/approve-team?team_id={team_id}` |
| 线上公开清单中的旧接口 | `POST /api/matches/registerations/{reg_id}/approve` |

旧接口路径中的 `registerations` 确实是线上清单中的拼写，并且接收单条报名记录的 `reg_id`，不能用队伍 `team_id` 替代。本次错误源于前端与线上后端版本不一致，不是队伍列表中的按钮没有绑定成功。

## 本地修正

- 请求层保留 HTTP 状态码，便于区分接口不存在、业务记录不存在和权限问题。
- 仅当整队审核返回 HTTP 404 且 `detail` 为 FastAPI 默认的 `Not Found` 时，显示「当前服务器版本不支持整队报名审核，请更新后端后重试」。
- 「该队伍未报名此赛事」等业务 404 保留后端原文；401、403 仍按登录和权限错误处理。
- 不自动重试旧单条审核接口。当前整队审核包含阵容与资格校验、全部报名记录同步通过以及赛事进度创建；回退旧接口不能保证这些业务约束，也不能保证整队审核的原子性。
- 本地现有整队审核路由及审批业务逻辑未因本次提示修正而更改。前端没有在失败时伪造成功或更改队伍状态。
- 同轮新增的报名时间编辑接口也区分缺失路由与业务错误；旧后端会明确提示「当前服务器版本不支持报名时间设置，请更新后端后重试」。

## 部署范围与验收

**改完本地小程序只能让错误提示清楚；实际恢复线上整队审核需要部署匹配版本的后端。**

1. 将当前已验证的后端代码及对应依赖同步到服务器既有项目目录。应部署一致版本的 `backend/`，包括 `app/routers/match.py`、`app/services/match_service.py` 及其 `locking.py` 等依赖；不能只新增路由或只上传小程序。
2. 保留服务器现有环境配置、数据库及上传文件卷。本次接口问题不需要新增数据库字段或清理报名数据。
3. 本项目 Compose 服务名为 `backend`，Dockerfile 使用 `COPY app ./app` 将代码写入镜像。因此需要重新构建并更新该服务，单纯重启旧容器不会载入新代码。在已确认且同步代码的服务器项目目录（部署文档示例为 `/opt/cs2`）可执行：

   ```bash
   docker compose up -d --build --no-deps backend
   docker compose ps backend
   docker compose logs --tail=80 backend
   ```

4. `nginx.conf` 使用 `upstream backend { server backend:8000; }` 静态上游。确认后端启动正常后运行 `docker compose exec nginx nginx -s reload`，使 Nginx 重新解析重建后端的容器地址。
5. 只读确认线上 `/openapi.json` 已出现 `POST /api/matches/{match_id}/registrations/approve-team`；本轮新增的报名时间编辑接口 `PUT /api/matches/{match_id}/registration-window` 也应随同版本部署并确认存在。随后由管理员在确认队伍资格后按正常流程审批。部署后若提示「该队伍未报名此赛事」或资格校验失败，应按具体业务提示处理，不再视为缺失路由。

本次没有执行生产部署；上述命令是待部署步骤，并非已完成操作。

