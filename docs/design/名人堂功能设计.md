## 两个板块

| 板块 | 对象 | 核心内容 |
| --- | --- | --- |
| 赛事冠军榜 | 每次比赛的冠军队伍 | 按届次/赛事展示冠军，长期保留荣誉记录 |
| 选手段位榜 | 平台选手 | 按已认证的当前段位展示最强选手 |

两个板块分别展示团体比赛荣誉与个人段位排名，不能把最高水平分选手当作赛事冠军。

## 赛事冠军榜

使用「赛事名称 + 日期 + 冠军队徽/队名」卡片，展示决赛比分与对手，支持展开冠军阵容。按比赛时间倒序展示；未设置比赛时间的历史记录使用赛事创建日期。

冠军必须来自当前六强赛制的完整决赛链：两场四分之一决赛、两场半决赛和一场决赛共五场均结束，比分与胜者一致，半决赛与决赛的参赛队伍符合前轮晋级结果。仅将赛事状态改为「已结束」、排名第 1、只完成半决赛或缺少对阵，都不会生成冠军。

首次提交有效决赛结果时，在 `champion_snapshots` 表保存双方决赛队伍的名称、队徽和当时成员资料，与比分在同一事务提交。后续更名、退队或更新段位不改写档案。更正决赛比分时同步冠军；改判另一队获胜时，使用该队首次保存的阵容。无效比分会撤回公开展示，之后恢复有效结果时继续使用原快照。

档案不依赖赛事、队伍或用户的外键，删除原记录后仍保留历史荣誉。接口用 `match_available` 表示原赛事是否仍存在，页面据此隐藏失效的赛事详情入口。

上线前已有的比赛需显式调用 `backfill_champions` 归档，普通查询不会写入或补齐数据。回填只接受上述完整决赛链，重复执行不会覆盖已有快照。历史数据无法证明夺冠当天的阵容和时间，因此标记 `snapshot_source=backfill`、`awarded_at=null`，页面提示「历史阵容为归档时记录」。

## 选手段位榜

展示选手昵称、头像、完整段位徽章和 S 段星数，不展示学号、认证截图等资料。

以已生效的认证段位为排名依据，待审核的段位申请不参与排名。现有段位顺序为：

`D < C < C+ < C++ < B < B+ < B++ < A < A+ < A++ < S0 ... S50`

S 段按星数降序排序，金 S、钻 S、魔王 S 使用现有徽章映射。不能按段位文字的字母顺序排序，也不能单独按可调整的水平分代替段位排名。

同段同星显示并列名次，例如 `1、1、3`；并列项按固定用户 ID 稳定排列。旧值 `S` 与 `S0` 同级。数据库先计算完整排名再分页，水平分不参与排序。

排名依据已生效的 `User.rank`；待审申请不会覆盖原段位。学籍认证与段位认证是不同流程，榜单不额外要求学籍已认证。

## 页面与接口

名人堂页 `/pages/hall/hall` 设置「赛事冠军」「选手段位」两个页签，首页及抽屉导航已接入入口。前者使用奖杯与冠军队伍卡片，后者展示平台最高段位及排行榜，沿用深蓝、青绿和少量金色。两个列表分别加载和分页，支持下拉刷新、空状态、失败重试及展开阵容。

| 公开只读接口 | 内容 | 默认每页 |
| --- | --- | --- |
| `GET /api/hall/champions` | 冠军档案、决赛比分、阵容、赛事可用状态 | 20 |
| `GET /api/hall/players` | 已认证选手段位与名次 | 50 |

两接口接收 `offset`、`limit`，单页上限 100，返回 `items`、`total`、`offset`、`limit`、`has_more`。公开资料不包含学号、认证截图、微信标识或审核详情。
